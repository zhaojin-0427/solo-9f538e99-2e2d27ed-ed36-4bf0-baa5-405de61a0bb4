# 共享电单车电池寿命分析

用 Flask + SQLite 做的电池随访台账与 Kaplan–Meier 无故障概率页面，按机龄帮助车队安排抽检。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>（可用 `APP_PORT` 改端口）。数据库保存在 `battery-data` 卷中，
容器以非 root 用户运行并带健康检查。

本地开发：

```bash
python3 -m pip install -r requirements.txt
python3 app.py            # 或 BATTERY_DB=/tmp/x.db python3 app.py
python3 -m pytest tests -q
```

## 使用流程

1. 在 **上传随访** 页提交 CSV（UTF-8 或 GB18030；可先下载模板）。
2. 在 **寿命分析** 页选择截止日（UTC），查看每个发生过故障的机龄对应的在险数、故障数
   和 KM 无故障概率。
3. **台账** 页查看当前生效的每块电池记录。

### CSV 格式

必需列（也接受对应中文表头）：

| 列 | 含义 |
| --- | --- |
| `battery_no` | 电池号，文件内必须唯一 |
| `activation_date` | 启用日（UTC，`YYYY-MM-DD`） |
| `followup_start` | 随访首日 |
| `followup_end` | 随访末日 |
| `outcome` | `failure` / `censored`（也接受“故障 / 正常结束”） |

可选 `action` 列：`insert` / `update` / `delete`（或“补录 / 更正 / 删除”）。
留空时自动判断：新电池号新增，已存在则视为更正（同号旧记录被覆盖）。

日期接受 `YYYY-MM-DD`、`YYYY/MM/DD`、ISO 8601 时间戳；带时区的时间会先换算为 UTC 再取日期。

### 校验规则

* 整份文件先校验再写入；任一行出错则整份拒绝，数据库和已有曲线都不受影响。
* 同一文件内电池号重复、日期缺失/非法、随访首日晚于末日、随访末日早于首日都会报错并给出行号。
* 同一电池号的更正覆盖旧值，删除则从曲线中移除。

## 统计口径

* 机龄 = 随访日期 − 启用日，按整天计算。
* 随访截到所选截止日：尚未入组的电池（随访首日晚于截止日）不计；
  截止当天发生的故障照计；截止当天结束随访的电池仍计入当天在险数。
* 同一机龄先入组再计故障；某机龄当天结束时先计入在险数再删失。
* 截止日后的故障按该日删失处理。
* KM 无故障概率逐故障机龄相乘：`S(t) = ∏ (1 − d_i / n_i)`，只列出发生故障的机龄。

### 截止日覆盖全部随访末日时的优化

分析页按当前截止日选择读取路径，两条路径的指标完全一致：

* **覆盖路径**：当所选截止日不早于任何一次随访末日（即不再需要截断）时，读取只按
  `(入组机龄, 结束机龄, 结局)` 聚合的 `age_counts`。此时启用日不再影响结果，
  读取行数只随不同的入组机龄/结束机龄/结局组合数增长，与电池数量、启用日数量无关。
  截止当天结束的电池仍计入截止日在险数（由 `followup_end_counts` 精确给出）。
* **截断路径**：若仍有随访晚于截止日结束，则沿用原口径，读取按启用日分组的
  `summary_counts` 并按启用日逐组截断。

“是否有随访超过截止日”与页面指标取自同一已提交快照（同一个读事务），
因此二者不会互相矛盾；WAL 模式下该读事务不会阻塞另一窗口的导入。

## 存储结构

| 表 | 用途 |
| --- | --- |
| `battery_ledger` | 台账：每块电池当前一条记录 |
| `battery_summary` | 每块电池 1 条汇总记录（更正原地覆盖并递增 `revision`） |
| `battery_summary_usage` | 每块电池汇总记录的终身用量，补录/更正/删除各计 1 次，上限 6 条 |
| `summary_counts` | 按启用日与机龄预聚合的计数；截断路径只读这张表 |
| `age_counts` | 只按 (入组机龄, 结束机龄, 结局) 预聚合；覆盖路径只读这张表 |
| `followup_end_counts` | 按随访末日（绝对日期）计的人数；用于判断是否需要截断与截止日在险数 |
| `aggregate_state` | 标记旧库已完成一次性聚合回填 |
| `import_batches` | 导入批次统计 |

每块电池的补录、更正、删除合计最多写入 6 条汇总记录；超出时整份文件被拒绝，
已有曲线不受影响。台账、汇总记录、用量计数和所有聚合计数在同一个 SQLite 事务中写入；
导入只按本批 (旧值 → 新值) 增量更新涉及的机龄与随访末日桶，不重读历史随访，也不需要
重算其他电池。导入失败整体回滚，分析页仍可按原有汇总计数查询（即使台账表本身不可用
也不影响曲线）。旧 SQLite 卷在启动时从已聚合的 `summary_counts`（或 `battery_summary`）
一次性回填 `age_counts` / `followup_end_counts`，原有随访直接纳入优化，无需重新导入。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/survival?cutoff=YYYY-MM-DD` | 寿命分析页 |
| GET/POST | `/upload` | 上传页面 / 导入 CSV |
| GET | `/ledger` | 当前台账 |
